==================================================
1. PRODUCT VISION
==================================================

EduRef AI không phải chatbot thông thường.

Đây là một:

"HUMAN-IN-THE-LOOP AUTONOMOUS AI AGENT WORKSPACE"

AI có khả năng:
- nhận yêu cầu,
- phân tích,
- lập kế hoạch,
- gọi tool/API,
- thực hiện nhiều bước,
- quan sát kết quả,
- tự tiếp tục với hành động an toàn,
- dừng lại khi gặp hành động nhạy cảm,
- yêu cầu con người phê duyệt,
- cho phép con người can thiệp/bẻ lái bất kỳ lúc nào.

Triết lý:

AI làm phần việc nặng.
Con người luôn hiểu chuyện gì đang xảy ra.
Con người luôn giữ quyền kiểm soát cuối cùng.

UI phải tạo cảm giác:

"Agent đang làm việc cho tôi"

thay vì:

"Tôi đang quan sát một hệ thống kỹ thuật phức tạp."

12. RISK COMMUNICATION
==================================================

Không dùng RED cho mọi thứ.

Color semantics:

Blue:
normal interaction / primary navigation

Green:
completed / successful / safe confirmation

Amber:
needs attention / human approval

Red:
destructive / failure / dangerous action only

Purple/Violet:
reasoning / AI-specific metadata nếu cần

neutral/system information

Mục tiêu tâm lý:

13. APPROVAL BUTTON ERGONOMICS
==================================================

Apply Fitts's Law.

Buttons phải nằm sát decision context.

Minimum height:
40–44px preferred.

Khoảng cách giữa destructive và positive actions:
>= 16px.

Primary:

Approve & Continue

Secondary:

Modify

Destructive:

Reject & Stop

Không đặt Approve và destructive button quá sát nhau.

Nếu action irreversible:

Không autofocus nút Approve.

Nếu action low/medium risk có thể sử dụng keyboard shortcut.

==================================================
31. IMPORTANT UX DETAILS
==================================================

Implement these carefully:

1. Thinking automatically collapses after completion.

2. Approval automatically scrolls into visible area,
but must NOT steal scroll if user intentionally scrolled upward.

3. Pending approval remains discoverable.

If user scrolls away, show:

◆ 1 approval waiting

4. Never hide Stop/Pause while Agent is actively executing.

5. User intervention must be visually distinguishable from original prompts.

6. Every important Agent action should leave an audit trail.

7. Do not show raw chain-of-thought by default.
Show concise reasoning summaries and observable action rationale.

8. User must always know whether an action:
- has NOT happened,
- is happening,
- has completed,
- requires approval.

==================================================
35. ACCEPTANCE CRITERIA
==================================================

The redesign is successful when:

A new user can understand within ~5 seconds:

- what task is running,
- what the Agent is doing,
- whether they need to do anything.

When approval appears:

- user immediately notices it,
- understands WHY approval is needed,
- understands WHAT will happen,
- can Approve / Modify / Reject without searching elsewhere.

During autonomous execution:

- user feels informed,
- but not overwhelmed.

During long-running tasks:

- user can leave and return,
- quickly understand progress.

Advanced users:

- can inspect detailed activity/logs.

Normal users:

- never need to read technical logs.

Most importantly:

The interface should feel like a modern AI assistant with controlled autonomy,
not like an admin dashboard with a chatbot embedded inside it.
